Detectable gaps

These are the gaps that leave evidence behind. Reporting from the relay to the daemon is asynchronous and one-way, so an event the daemon accepted and then failed to write leaves nothing to count — it cannot be told apart from no event having been sent. Read these as detected, never as all.

Sessions — newest first
#sessionstateagentconnectorclient calls recordeddeniedoutcomesanomaliesstarted

unfinished means no session.end was recorded. That covers a session running right now and one whose daemon died without writing an end — the journal cannot tell them apart, so neither can this page.

denied counts the calls Nim refused. A refused call never gets an outcome, so calls recorded minus outcomes is not a count of anything that went missing.

connector and client are labels the relay reported for itself. They are self-asserted, not facts Nim established.

agent is the opposite kind of thing: the enrolled program the daemon derived from the kernel — the process that spawned the relay, and the file it was executing. Empty when no enrolment matched, which is the ordinary state.

Rules — what is denied
effectagentconnectortoolcreated

What may happen, not what did. A rule allows or denies one tool for every session, for one enrolled agent, or on one connector; * is a default. The most specific rule wins, deny beats allow at equal specificity, and a call no rule names is allowed. nim policy explain shows which rule decides a call.

Agents — enrolled programs
namestateenrolledexec path

An enrolment is as privileged as running Nim: anything that can execute this binary as this user can enrol an agent or replace an existing one.

STALE means the file at that path is no longer the one that was enrolled — not a sign of tampering, just that it needs to be repeated: a device number can change across a reboot, and a self-updating program becomes a different file. Where this platform has no way to check a file's identity at all, state reads unknown rather than guessing.
